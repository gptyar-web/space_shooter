## راه‌اندازی

۱. تنظیمات GitHub Pages مخزن را بررسی کنید؛ اگر انتشار از شاخهٔ main و ریشهٔ مخزن باشد، نشانی مورد انتظار این است:

https://gptyar-web.github.io/space_shooter/

گردش کار GitHub Actions برای انتشار مستقیم فایل‌های وب در مخزن قرار داده شده است. در تنظیمات Pages لازم است GitHub Actions انتخاب و استقرار موفق تأیید شود.

۲. پنج migration با نام‌های `001_initial.sql`، `002_secure_order.sql`، `003_secure_config.sql`، `004_registration_rate_limit.sql` و `005_bale_invoice_recovery.sql` برای پروژهٔ متصل آماده و اعمال شده‌اند؛ روی همان پروژه مجدداً بدون بررسی اعمال نشوند. migration چهارم rate-limit ثبت‌نام را اعمال می‌کند و migration پنجم لغو فاکتور ناموفق و کنترل تراکنش تکراری را ایمن می‌کند.

۳. دو تابع در Supabase منتشر شده‌اند؛ پس از تغییر کد آن‌ها، مجدداً با Supabase CLI منتشرشان کنید. هر دو به علت ثبت‌نام عمومی و Webhook، تنظیم no-verify-jwt دارند؛ کنترل احراز هویت داخل کد توابع انجام می‌شود.

    supabase login
    supabase link --project-ref efibfevyiepkwpnobaro
    supabase functions deploy space-shooter-api --no-verify-jwt
    supabase functions deploy space-shooter-bale --no-verify-jwt

در توابع، SUPABASE_URL و SUPABASE_SERVICE_ROLE_KEY فقط از محیط امن سرور خوانده می‌شوند. هیچ توکن خصوصی را در GitHub یا فرانت‌اند منتشر نکنید.

۴. پس از ساخت حساب از سایت، مالک پایگاه داده باید یک بار مدیر نخستین را مشخص کند (YOUR_USERNAME نام کاربری واقعی مدیر است):

    insert into public.ss_admins(id)
    select id from public.ss_profiles where username = 'YOUR_USERNAME'
    on conflict do nothing;

هیچ رمز مدیر پیش‌فرض یا امکان ارتقای مدیر از مرورگر وجود ندارد.

۵. در پنل مدیریت، قیمت هر سکه به ریال، لینک رسمی https://ble.ir/...، توکن بازوی بله و توکن کیف پول بله را ثبت کنید. توکن‌ها فقط سمت سرور در ss_private_config ذخیره می‌شوند و در خروجی عمومی قابل خواندن نیستند. قیمت پیش‌فرض صفر است، بنابراین تا پیکربندی امکان فروش وجود ندارد. تنظیمات ثبت‌شده باعث فراخوانی setWebhook می‌شوند.

۶. ابتدا با توکن آزمایشی کیف پول بله و سپس سفارش کوچک واقعی، روش‌های sendInvoice، answerPreCheckoutQuery، successful_payment و inquireTransaction را کنترل کنید. هیچ پرداخت واقعی در این تحویل انجام یا آزمایش نشده است.

- پاداش ورود متوالی: روز اول ۱۰۰، روز دوم ۲۰۰، روز سوم ۳۰۰ سکه و به همین ترتیب، براساس تاریخ تهران.

- خرید سکه در بله با شمارهٔ ارسال‌شده از حساب بله، کد اتصال ۱۲ حرفی از حساب وب، سفارش، تخفیف، صورت‌حساب و استعلام پرداخت.
- واریزی‌ها با شماره سفارش، مبلغ به ریال، تعداد سکه و وضعیت.

- نمایش موجودی و دکمهٔ «+» در بالای صفحات غیر از میدان نبرد؛ بازخوانی موجودی هر ۵۰۰ میلی‌ثانیه.
- پنل مدیر: فهرست و ویرایش کاربران، فعال/غیرفعال‌سازی با علت، اصلاح موجودی با ردیف مالی ثبت‌شده، بسته‌ها، کد تخفیف درصدی/ریالی، **تقویم انتخاب تاریخ شمسی شروع و پایان به همراه ساعت، یا اعتبار زمانی نامحدود**، تعداد استفادهٔ محدود/نامحدود، ویرایش و غیرفعال‌سازی تخفیف‌ها، اطلاعیه و مدیریت تیکت و سفارش.

## محدودیت‌های امنیتی قبل از بهره‌برداری عمومی

۱. احراز مالکیت شماره در ثبت‌نام وب هنوز OTP پیامکی ندارد. برای جلوگیری از اتصال شمارهٔ دیگران در بله، هر دو عامل ارسال مخاطب حساب بله و کد تولیدشده در حساب وب لازم‌اند. بهتر است OTP به ثبت‌نام اضافه شود.

۲. سرور بازهٔ اجرای بازی، تعداد دشمن، امتیاز و شرط باز شدن مرحله را بررسی می‌کند، اما تمام حرکت‌ها/برخوردها را مجدداً شبیه‌سازی نمی‌کند. نتیجهٔ جعل‌شدهٔ مرورگر هنوز ممکن است؛ برای اقتصاد سکهٔ واقعی باید replay validation یا سرور بازی مقتدر پیاده شود.

۳. سهمیهٔ کد تخفیف هنگام ایجاد سفارش رزرو می‌شود و در صورت عدم تأیید ارسال صورتحساب به بله، آزاد می‌گردد. برای سفارش‌هایی که صورتحسابشان ارسال شده اما هرگز پرداخت نشده‌اند، انقضا و آزادسازی خودکارِ ایمن هنوز پیاده‌سازی نشده است.

۴. اگر تأیید پرداخت بله موقتاً ناموفق باشد، مکانیزم بازیابی دوره‌ای و reconciliation هنوز اجرا نشده است. تا زمان تکمیل، این بخش برای پرداخت واقعی آمادهٔ تولید نیست.

۵. آپلود تیکت از bucket خصوصی Supabase Storage استفاده می‌کند. سقف پیش‌فرض ۳۰ MiB و سقف طراحی‌شده فعلی برای مدیر ۵۰ MiB است؛ محدودیت جهانی پلن Supabase نیز باید رعایت شود.

۶. Rate-limit سمت سرور برای ثبت‌نام اعمال شده است (سراسری، بر اساس شمارهٔ هش‌شده، و بر اساس IP در صورت دسترسی به آن). هنوز CAPTCHA، حفاظت از حملهٔ توزیع‌شده و OTP پیامکی افزوده نشده است؛ پیش از بازکردن ثبت‌نام گسترده تکمیل شوند.

۷. بررسی امنیتی RLS، مجوزهای Edge و Webhook و بازآزمایی گزارش‌های مالی قبل از بهره‌برداری الزامی است.

## بهبود امنیت و بازیابی پرداخت‌ها (۲۶ اکتبر ۲۰۲۶)

- Migrationهای 006، 007 و 008: احراز هویت حساب بله، ثبت امن شناسه پیش‌پرداخت و بازیابی خودکار تراکنش‌های قابل استعلام هر ۱۵ دقیقه، با رمز اختصاصی ایجادشده در Vault. فایل 008 اتصال‌های قبلی بله را فقط در صورت وجود کد مصرف‌شده و نشست تأییدشده به قالب جدید منتقل می‌کند.
- تأیید مالکیت شماره از ارسال مخاطب خود کاربر در بله و کد ۱۲ حرفی یک‌بارمصرف در حساب وب انجام می‌شود. این روش OTP پیامکی نیست؛ برای جلوگیری کامل از ثبت اولیه با شمارهٔ دیگران سرویس مستقل پیامکی لازم است.
- دریافت پیام پرداخت موفق به‌تنهایی موجب شارژ نمی‌شود. تراکنش باید از بله استعلام و وضعیت paid، شناسهٔ تراکنش، مبلغ و مالک تأیید شوند.
- در صورت قطع شبکه هنگام ارسال فاکتور، سفارش و سهمیه تخفیف بدون استعلام لغو نمی‌شود. فاکتورهای معلق بدون شناسه پیش‌پرداخت، نیازمند بررسی دستی‌اند.
- نتیجه بازی علاوه بر امتیاز و تعداد دشمن، با جان‌ها، مدت بازی و ساعت سرور تطبیق داده می‌شود، ولی بازپخش معتبر سمت سرور هنوز پیاده نشده است؛ ضدتقلب کامل محسوب نمی‌شود.
- قبل از فروش عمومی حتما پرداخت آزمایشی بله، تأخیر یا تکرار وب‌هوک، استعلام تراکنش، Cron، رفتار موبایل و احراز شماره با حساب واقعی آزمایش شود.

### پذیرش و نظارت سفارش

- بخش «مدیریت ← سفارش‌ها» سفارش‌های دارای شناسه پیش‌پرداخت را در صف استعلام و سفارش‌های معلق فاقد شناسه که بیشتر از ۲۴ ساعت گذشته‌اند، برای بررسی دستی مشخص می‌کند.
- اجرای خودکار job در PostgreSQL با نام `ss_bale_reconcile_15m` از طریق Vault انجام می‌شود. برگشت موفق HTTP ۲۰۰ برای تست ساختگی بدون تراکنش در زمان راه‌اندازی بررسی شده، اما آزمون پرداخت واقعی در بله هنوز لازم است.
